# Step 3 — Smart Savings

Status: implemented on `feature/smart-savings` (draft PR, stacked on Step 2B). **Not deployed. Never moves money.**

## What it answers
"How much can I genuinely save for the rest of this month, given what has actually happened in my bank, and where should it go?" It sits at the top of the Savings page, above the tabs, so it does not wait for the Savings workspace to load.

## Planned vs actual
| | Source | Changed? |
|---|---|---|
| **Planned** | Each pot's existing *Monthly Equivalent* (the Savings module's figure from estimated take-home pay, bills and debts) | No, only read |
| **Actual** | This calendar month's bank activity (Step 2A classifier), what is still due (Step 2B timeline and Finance Payments), and what has already been saved | New, read-only |

## The calculation (`Backend/Savings/SmartSavingsCalculator.js`, pure)
```
genuinely available =
    income received        (confirmed salary, other income, interest)
  - spending               (everyday)
  + refunds
  - bills, subscriptions and debts already paid
  - unconfirmed outgoing   (needs-confirmation and unrecognised debits)
  - pending card payments
  - still to pay before month end  (Step 2B bills/subscriptions + unpaid debt repayments)
  - already saved this month       (Monzo pot deposits less withdrawals)
```
- **Conservative by design.** Unconfirmed or pending *income* is not added; unconfirmed or pending *outgoings* are subtracted. A salary expected later in the month is planned, not actual, so it doesn't count.
- **Each bank transaction is counted once.** One already in, or possibly duplicated by, the Money Movements ledger still counts, just once. A bill or debt repayment whose bank transaction is already in this month's actuals is not also counted as "still to pay".
- **Transfers to your own other accounts** are neither spending nor subtracted. The preview warns when there are any, because bills paid from that other account would make the real available figure lower.
- **Past-due payments without bank confirmation**, and payments with **no known amount**, produce a warning. Unconfirmed past-due payments still count as money to pay; unknown amounts aren't deducted.

## Suggestion (uses the existing Savings Settings)
- **Percentage of Disposable Income:** `Disposable Income Savings %` × the genuinely available amount.
- **Fixed Monthly Amount:** the fixed amount, less what was already saved this month, and never more than is available.
- **Maximum Monthly Savings** caps the month's *total*, counting what was already saved.
- Nothing is suggested when no confirmed income has arrived or the month is overspent; a warning explains why.

## Split across existing pots
1. Active **Fixed Amount** pots first: their monthly plan, less what was already deposited this month.
2. The rest is split by **Allocation %** across active percentage pots. If allocations add up to more than 100%, they are scaled down to 100% (with a warning); if less, the remainder stays unallocated.
3. Inactive pots, and pots that have reached their goal, get nothing.
4. "Saved this month" comes from Monzo for pots linked to a Monzo pot, and from Savings History (undone entries excluded) for the others.
5. Amounts round down to the penny, and any leftover pennies are shown as unallocated.

Goal progress (e.g. **Mortgage deposit**) shows the current figure and the figure after this suggestion. Pots and Life Goals are only read, never changed.

## Confirmation workflow (the only write)
The panel lists this month's queued Savings Contributions that aren't yet deposited. Each one shows any matching Monzo pot deposit (same linked pot, same amount, within 3 days); one deposit can support only one contribution.

**I moved it - record** shows a confirmation that you, not Pay Tracker, moved the money. The server then checks that the contribution still exists, isn't already deposited and still has the amount you saw. It then calls the **existing** `markContributionDeposited` path, the same as the Savings → Contributions tab.

Existing behaviour, unchanged: marking a contribution deposited adds it to the pot's Current Balance. For a Monzo-linked pot, the next Monzo pots sync (15-minute freshness) resets the balance to the real Monzo figure, so it may briefly show the deposit twice.

## Tests
- `runSmartSavingsTests()`: 35 pure checks, safe in the live editor.
- `Tests/node/SmartSavings_Scenarios.cjs`: 7 end-to-end scenarios on in-memory copies of every sheet it reads. They cover read-only behaviour (nothing changed, no sheet created), the guarded confirmation, and that no Monzo or UrlFetch call is reachable from Smart Savings.
- Mutation-checked: 17 deliberate breaks are each caught.
- The UI was checked at desktop and 375px widths in a local harness using real calculator output. On phones the pot table becomes labelled blocks. It hasn't been seen in the deployed app yet.
