**Rules for the whole checklist:** nothing here touches production until step 10, and step 10 needs your explicit go-ahead. Pay Tracker never moves money; nothing in v3.3 can.

Tick each box. Stop at any ✗ and report it.

## 3. Preview what the first v3.3 sync will treat as manual corrections (read-only)

1. In the **staging copy** editor run `previewCalendarManualOverrides()`. It changes nothing.
   - [ ] Number listed: ____ . Every listed row is one you really did correct by hand (for example the 24h → 4h night-shift corrections). If a row is listed that you did *not* change, report it before going further.

## 5. Deploy to the isolated staging application (after your approval)

1. Staging copy → Extensions → Apps Script → note its **Script ID**.
2. On the development machine, *temporarily* point clasp at it and push the RC:

   ```bash
   git -C ../Pay-Tracker-rc checkout release/v3.3.0-rc1
   cd ../Pay-Tracker-rc && clasp push --force   # with .clasp.json scriptId = the STAGING Script ID
   ```
   Don't commit the changed `.clasp.json`.
   - [ ] Pushed to the **staging** Script ID (checked twice)
3. Staging editor → **Deploy → New deployment → Web app**, execute as *Me*, access *Only myself*.
   - [ ] Staging URL: ____

5. **Triggers are not copied.** Leave it that way: no scheduled syncs in staging.
6. Staging editor → run `runAllPayTrackerTests()` **in staging only**. Some suites write test rows into the sheet they run against, so never run them on production.
   - [ ] All suites pass, except the 5 Staffline "real Staffline detail is imported for Timesheet …" checks if the portal data isn't present (those 5 need the real imported data; the other 50 Staffline checks pass offline)

## 8. Verify Savings calculations against real records (staging)
1. Savings page → Smart Savings:
   - [ ] "Income received" equals money actually received in Monzo this month (salary/interest, not transfers between your own accounts)

## 11. Rollback
- **Code:** Deploy → Manage deployments → production deployment → Edit → select the previous version (**@143**) → Deploy. Same URL, takes effect immediately. Or `clasp deploy -i <production deployment ID> -V 143`.
- **Data:** v3.3 adds **no sheet columns and no schema changes**. The only new writes are: Manual Override statuses on Calendar Sync Records, the corrected settle-update on pending Bank Transactions rows, and Savings History notes. If data needs reverting, restore the "Before v3.3" named version (step 1.2), or copy individual sheets back from it.
- **Cache:** the Upcoming Payments cache (CacheService, 6 h) is ignored by @143 and expires by itself.
